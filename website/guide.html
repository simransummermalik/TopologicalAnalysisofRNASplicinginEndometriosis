Let’s run Splice Girl.

Keep your terminal open beside this page. These commands use the project’s synthetic examples; you do not need to download sequencing data. The website explains the commands. It does not run them for you.

Seven steps. Start with set up.

1. Get the project and check Rust

Download or clone the repository, then open its folder in your terminal. You want the folder containing Cargo.toml and README.md, not website/.

terminal · check the folder
pwd
ls Cargo.toml README.md

pwd prints your current folder. ls should list both files. If it cannot find them, use cd to move into the actual project folder first.

terminal · check Rust
rustc --version
cargo --version

You need Rust 1.85 or newer. Cargo comes with Rust. If either command is missing, follow the Rust installation instructions, reopen the terminal, and check again.

Ready when: both project files exist and both version commands print a version.

2. Try one graph with a known answer

terminal · from the project root
cargo run -- analyze tests/fixtures/exon_skip.tsv

The first run compiles the program, so allow it to finish. cargo run -- runs Splice Girl from the project source; everything after -- is an instruction to Splice Girl.

What is the data? A made-up, three-exon graph with two routes: E1–E2–E3 and E1–E3. The junctions have equal read support.

What does the code do? Read the table, build the graph, normalize its counts, separate gradient/cycle signals and check the calculation.

cycle_fraction: 0.1111111111
checks: PASS

Look for: about 0.1111, or one ninth. That is this toy graph’s expected mathematical answer, not a disease score.

Do I have to type “cargo run” every time?

No. You can install the shorter command from this project folder:

cargo install --path .
splice-girl --version

Then replace cargo run -- with splice-girl. Keep running from the project root so the example paths still resolve. An installed command must be reinstalled after source changes; it does not update itself.

3. Use the terminal menu

terminal
cargo run -- --start

You should see our ASCII banner and a numbered menu. Follow each prompt in order:

  1. Type 1 for “Analyze a junction TSV” and press Return.
  2. At “Junction TSV path”, enter tests/fixtures/cycle.tsv.
  3. At “Output folder”, press Return without typing anything. This prints the result without saving a folder.
  4. Read the result, then press Return to go back to the menu.
  5. Type q and press Return to quit.

Look for: cycle_fraction: 1.0000000000 and checks: PASS. This second fixture is an equal-weight directed cycle, so its expected answer is one.

4. Check an input before using it

terminal
cargo run -- validate examples/demo/junctions.tsv

The program checks the table, graphs and mathematical identities. Expect validation_status: PASS.

The input has five columns. Here is one illustrative row:

sample_id   gene_id     from   to   count
case_01     GENE_DEMO   E1     E2   100

The real file uses tabs between columns. The count says how much read support that sample has for that junction. You do not need to type this table; it is already in the project.

Why does adding the demo manifest produce an error? 
cargo run -- validate examples/demo/junctions.tsv examples/demo/manifest.tsv

This intentionally fails with exit status 1. The demo contains orphan_01 without metadata, and control_03 in the metadata without junctions. The error shows that the program noticed both. It is an expected demonstration, not a failed installation.

5. Compare the example groups

terminal
cargo run -- compare examples/demo/all_genes.tsv examples/demo/manifest.tsv

all_genes.tsv contains two synthetic genes and four measured samples. manifest.tsv supplies the case/control labels. Its extra control_03 has no data and is explicitly excluded.

Expected case-minus-control differences
GeneDifference
GENE_HIGH_CYCLE+0.5555555556
GENE_LOW_CYCLE−0.5555555556

A positive difference means the example case group has a larger mean cycle fraction. Negative means the control group has a larger mean. These are descriptive differences, not p-values.

Look for: two cases and two controls contributing to each gene. A missing measurement must not become an invented zero.

6. Draw a graph from the input

terminal
cargo run -- visualize case_02 GENE_DEMO \
  examples/demo/junctions.tsv target/website-demo-graph.svg

case_02 chooses the sample; GENE_DEMO chooses the gene. The final path is the new file to create.

On macOS, open it with:

terminal · macOS only
open target/website-demo-graph.svg

On another system, open the SVG in a web browser using your file manager. You should see the same graph’s observed, gradient and cycle signals side by side, plus a junction table.

Repeating the step? Use a new filename, such as target/website-demo-graph-2.svg. Splice Girl refuses to replace an existing figure.

7. Save a report you can read

terminal
cargo run -- report examples/demo/all_genes.tsv \
  examples/demo/manifest.tsv --output target/website-demo-report

This creates a folder containing tables, graph files and an HTML report. On macOS:

terminal · macOS only
open target/website-demo-report/report.html

On other systems, open that HTML file in a browser. No web server or internet connection is needed to view the saved report. Keep its whole folder together when sharing it.

Look for: two gene summaries, individual sample values, eight generated graph files and the explicit exclusions. Choose a new output-folder name for a repeat run.
